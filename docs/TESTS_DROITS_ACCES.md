# Tests des droits d'accès

Le sujet demande, pour **chaque règle d'accès**, « le test qui montre qu'un utilisateur non autorisé se fait bien refuser l'accès — pas seulement que celui qui a le droit y arrive ». Ce tableau relie chaque exigence à ses tests. Il est **vérifié automatiquement** : chaque nom de test cité existe dans `tests/` (le fichier est entre parenthèses).

La suite complète compte **279 tests**. La lancer : `python -m pytest` (la base doit tourner). Un test précis : `python -m pytest -k test_un_joueur_exclu_perd_l_acces_tout_de_suite`.

## Comment lire un refus

| Code | Sens | Exemple |
|---|---|---|
| 401 | pas de session valide | visiteur qui écrit |
| 403 | la ressource est publique, l'**action** est interdite | joueur qui veut clore un tournoi |
| 404 | la ressource n'est **pas visible** pour l'appelant, ou n'existe pas | non-membre qui lit un espace d'échange, avec le même message qu'une équipe inexistante |
| 400 | requête invalide, ou champ hors de la liste blanche du rôle | capitaine qui envoie `statutEquipe` |
| 409 / 422 | conflit d'état / règle métier | composition après clôture / poste déjà tenu |
